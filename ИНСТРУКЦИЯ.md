# Центр управления бизнесом — инструкция для системного администратора

Платформа — это программа, которая работает на виртуальной машине с Windows.
Сотрудники задают вопросы боту в MAX или Telegram, платформа собирает ответ из 1С,
Битрикс24, почты, Google Диска и маркетплейсов. Вы настраиваете всё это в браузере,
в **панели управления**.

Командная строка не нужна. Всё делается двойным щелчком по файлам `.bat`
и формами в браузере.

## 1. Требования к серверу

| Что | Минимум | Лучше |
|---|---|---|
| Windows | Windows 10 / Windows Server 2016 | Windows Server 2019–2022 |
| Процессор | 2 ядра | 4 ядра |
| Память | 4 ГБ | 8 ГБ |
| Диск | 20 ГБ свободно | 50 ГБ (база будет расти на следующих этапах) |
| Python | 3.11 | 3.12 |
| Интернет | нужен | постоянный, без блокировок |
| Доступ к 1С | сервер должен открывать адрес базы 1С (например, `https://192.168.1.10/ka`) | в одной сети с 1С |

**Важно про страну сервера.** Claude API (ядро платформы) не отвечает на запросы из
России. Если виртуальная машина стоит в России — понадобится прокси в другой стране
(указывается в «Настройках», см. раздел 6.1). Если машина за рубежом — наоборот,
российские сервисы (1С, маркетплейсы) должны быть ей доступны.

### Установка Python

1. Откройте в браузере **python.org** → **Downloads** → **Windows**.
2. Скачайте **Python 3.12** — «Windows installer (64-bit)».
3. Запустите. В первом окне **обязательно** поставьте галочку
   **«Add python.exe to PATH»** (внизу), затем **«Install Now»**.
4. Дождитесь «Setup was successful», закройте.

## 2. Установка

1. Распакуйте архив платформы в папку **`C:\Platforma`**.
   Лучше без русских букв и пробелов в пути: так меньше сюрпризов.
2. Нажмите на **`установить.bat`** правой кнопкой → **«Запуск от имени администратора»**.
   (Права администратора нужны, чтобы открыть порт в брандмауэре. Без них установка
   тоже пройдёт, но панель будет открываться только на самом сервере.)
3. Дождитесь надписи **«Установка завершена»** (1–3 минуты). Нажмите любую клавишу.
4. Двойной щелчок по **`запустить.bat`** — через несколько секунд откроется браузер
   с панелью. Окно с чёрным фоном можно закрыть — платформа работает в фоне.

Если на сервере нет интернета, попросите разработчика прислать папку **`wheels`**
с библиотеками, положите её рядом с `установить.bat` и запустите установку — она
пройдёт без интернета.

**Обновление платформы:** остановите её (`остановить.bat`), распакуйте новую версию
поверх старой **с заменой файлов** (папки `data`, `backups`, `logs` и файл `.env`
в архиве обновления отсутствуют, поэтому не пострадают), запустите `установить.bat`,
затем `запустить.bat`.

## 3. Первый вход

1. Панель на самом сервере: **http://localhost:8080**
2. Логин **admin**, пароль **admin**.
3. Панель сразу попросит придумать новый пароль (не короче 8 символов). Запишите его.
4. На странице **«Обзор»** есть список «Первоначальная настройка» — идите по нему
   сверху вниз.

Забыли пароль администратора? Запустите на сервере
**`сбросить-пароль-администратора.bat`** → нажмите **1**. Вход снова станет
admin / admin с требованием сменить пароль.

## 4. Автозапуск

Чтобы платформа сама запускалась после перезагрузки сервера (даже если никто не
вошёл в Windows):

1. Нажмите на **`автозапуск-включить.bat`** правой кнопкой →
   **«Запуск от имени администратора»**.
2. Дождитесь надписи «Готово».

В Планировщике заданий Windows появится задача **BusinessPlatform**. Она запускает
платформу через 30 секунд после включения сервера, не ограничена по времени работы
и перезапускает платформу, если та упала.

Выключить автозапуск — **`автозапуск-выключить.bat`**, тоже от имени администратора.

Когда включён автозапуск, платформа работает от имени системы. Поэтому
`остановить.bat` в этом режиме тоже запускайте от имени администратора.

## 5. Доступ снаружи: домен, сертификат, порт

Внутри офиса панель открывается по адресу `http://IP-сервера:8080`. Чтобы панель,
вход Google и бот работали из интернета, нужны три вещи.

### 5.1. Домен

Заведите поддомен, например **`panel.company.ru`**, у регистратора, где куплен домен
компании (reg.ru, nic.ru и т.д.): раздел DNS → добавить **A-запись**:
имя `panel`, значение — **внешний IP-адрес** офиса или виртуальной машины.

### 5.2. Порт на роутере

Если сервер за роутером — в настройках роутера сделайте **проброс портов**
(«Port forwarding», «Виртуальные серверы»): внешний порт **443** → IP сервера,
порт **443**. Если машина арендована у хостинга с «белым» IP — пропустите этот шаг.

В брандмауэре Windows порты 8080 и 443 открывает `установить.bat`, запущенный от
имени администратора.

### 5.3. Сертификат (HTTPS)

Без сертификата пароли идут по сети открытым текстом, а Google вообще не разрешит
вход по внешнему адресу.

Где взять:
- **Бесплатно:** программа **win-acme** (сайт win-acme.com). Скачайте, распакуйте,
  запустите `wacs.exe`, выберите «Create certificate (full options)» → «Manual input»
  → введите `panel.company.ru` → проверка «HTTP validation (self-hosting)» →
  хранилище **«PFX archive»** → укажите папку и пароль. Во время проверки порт 80
  должен быть проброшен на сервер. win-acme сам продлевает сертификат, но загружать
  новый файл в панель нужно вручную (раз в 2–3 месяца платформа напомнит).
- **Платно:** у регистратора домена (сертификат на год). Скачайте его в формате
  **PFX** или парой файлов **.crt + .key**.

Загрузка: **Настройки → HTTPS (сертификат)** → выберите файл → введите пароль от
файла → **«Загрузить сертификат»** → внизу **«Перезапустить платформу»**.

После этого:
- в **Настройках** укажите **Внешний адрес панели**: `https://panel.company.ru`;
- порт HTTPS по умолчанию 443 (меняется там же).

### 5.4. Если порт 8080 занят

Если при запуске видно «порт 8080 занят другой программой» — запустите
**`сменить-порт.bat`**, введите, например, `8081` и нажмите Enter, затем
`запустить.bat`. Когда панель работает, порт меняется и в **Настройках**.

## 6. Подключения: где брать каждый ключ

Раздел **«Подключения»**. У каждого подключения справа есть блок
**«Где взять данные»** с пошаговой инструкцией, а под каждым полем — подсказка.
Ниже — то же самое коротко.

Общие правила:
- **Пароли и токены хранятся зашифрованными.** После сохранения в поле видна только
  маска вида `********t123`.
- **Пустое поле пароля при редактировании = «оставить как было».** Чтобы заменить
  токен — просто вставьте новый.
- Лишние пробелы и переносы строк в токенах платформа убирает сама. Если в токен
  попали русские буквы (частая ошибка копирования) — панель скажет об этом прямо
  у поля.
- Кнопка **«Сохранить и проверить»** сразу проверяет связь и пишет результат
  по-русски с советом, что делать.

### 6.1. Ядро Claude (только одно)

1. **platform.claude.com** → войдите почтой компании.
2. **Billing** — привяжите карту, пополните баланс.
3. **API Keys** → **Create Key** → скопируйте ключ (начинается с `sk-ant-`).
4. В панели: **Подключения → Ядро Claude → Подключить**, вставьте ключ, выберите
   модель (по умолчанию Claude Opus 5), задайте месячный лимит расходов в долларах.

Если сервер в России, проверка скажет «Claude API отклоняет запросы из страны,
где находится сервер». Тогда: **Настройки → Прокси для зарубежных сервисов** →
адрес вида `http://логин:пароль@1.2.3.4:3128` (прокси в Казахстане, Европе и т.п.).
Через прокси идут только Claude, Google и Telegram.

### 6.2. 1С:Предприятие

Что нужно в 1С (делает программист 1С или вы в Конфигураторе):

1. Создайте пользователя **«Робот-интеграция»** с паролем:
   «Администрирование → Настройки пользователей и прав → Пользователи»,
   галочка «Аутентификация 1С:Предприятия».
2. В **Конфигураторе**: «Администрирование → Публикация на веб-сервере» — отметьте
   **«Публиковать стандартный интерфейс OData»** и
   **«Публиковать HTTP-сервисы расширений по умолчанию»** → «Опубликовать».
3. В 1С: «Администрирование → Синхронизация данных → **Настройка стандартного
   интерфейса OData**» — дайте доступ пользователю и отметьте объекты
   (номенклатура, контрагенты, заказы, остатки и т.д.).

В панели:
- **Адрес базы** — как в браузере при работе в 1С, например `https://192.168.1.10/ka`.
- **Пользователь** и **Пароль** — из шага 1 (русские буквы в имени допустимы).
- **Использовать OData** — оставить галочку.
- **Путь к HTTP-сервису** — пока можно не заполнять (понадобится на этапе 2).
- **Проверять сертификат** — если 1С открывается по IP и браузер ругается на
  сертификат, **снимите** галочку. Когда появится нормальный сертификат на домен —
  поставьте обратно.

### 6.3. Битрикс24

1. Битрикс24 → **Разработчикам** → вкладка **Другое** → **Входящий вебхук**.
2. Права: **CRM, Задачи, Пользователи**. **Сохранить.**
3. Скопируйте адрес из поля «Вебхук для вызова rest api»
   (вида `https://компания.bitrix24.ru/rest/1/abc123xyz/`) и вставьте в панель.

Адрес вебхука — это тоже секрет, он хранится зашифрованным.

### 6.4. Gmail и Google Диск

Делается в два шага: один раз — «ключи приложения», потом — каждый аккаунт кнопкой.

**Шаг 1. Ключи приложения Google** (один раз):

1. **console.cloud.google.com** под Google-аккаунтом компании → создайте проект.
2. **APIs & Services → Library**: включите **Gmail API** и **Google Drive API**.
3. **Google Auth Platform** (раньше «OAuth consent screen»): тип **External**,
   название, ваша почта. В разделе **Audience** нажмите **Publish app**.
   *Если этого не сделать, Google будет отключать доступ каждые 7 дней.*
4. **Clients → Create client** (или Credentials → Create credentials → OAuth client
   ID): тип **Web application**.
5. **Authorized redirect URIs** — добавьте адреса, которые панель показывает на
   странице «Google: ключи приложения» в блоке **«Адреса для Google»** (кнопка
   «Копировать»). Обычно это:
   - `http://localhost:8080/oauth/google/callback`
   - `https://panel.company.ru/oauth/google/callback`
6. Скопируйте **Client ID** и **Client secret** в панель → **«Сохранить и проверить»**.

**Шаг 2. Каждый аккаунт:**

1. **Подключения → Gmail и Google Диск → Подключить**.
2. **«Подключить аккаунт Google»** → выберите аккаунт → отметьте **все** галочки.
3. Если Google пишет «Приложение не проверено» — «Дополнительно» → «Перейти на
   страницу…». Это ваше собственное приложение.
4. Для следующего аккаунта — «Добавить ещё».

**Важно:** Google пускает только на адрес с доменом и https **или** на `localhost`.
Если домена ещё нет — подключайте аккаунты, открыв панель **на самом сервере** по
адресу `http://localhost:8080`. По IP-адресу (`http://192.168.…`) Google не пустит,
панель об этом предупредит.

### 6.5. Wildberries (по одному подключению на кабинет)

1. **seller.wildberries.ru** → имя кабинета справа вверху → **Настройки → Доступ к
   API** (или «Профиль → Интеграции по API»).
2. **Создать новый токен**: отметьте категории Контент, Статистика, Аналитика,
   Цены и скидки, Маркетплейс, Финансы, Продвижение. Пока подойдёт «Только чтение».
3. Скопируйте токен сразу — второй раз WB его не покажет.

Токен WB живёт 180 дней. Платформа заранее (за 14 дней) покажет жёлтое
предупреждение, что пора выпустить новый.

### 6.6. Ozon (по одному подключению на кабинет)

1. **seller.ozon.ru** → **Настройки → API-ключи**.
2. **Client ID** — число вверху страницы.
3. **Сгенерировать ключ**, роль **Admin read only** → скопируйте ключ.

### 6.7. Яндекс Маркет (по одному подключению на кабинет)

1. **partner.market.yandex.ru** → **Настройки → API и модули → Авторизационные
   токены** (API-ключи).
2. **Создать токен**, отметьте доступы к заказам, товарам, ценам, финансам, отчётам.
3. Скопируйте ключ целиком, он начинается с `ACMA:`.

### 6.8. Бот MAX (основной, только один)

Бота в MAX создаёт организация:

1. Зарегистрируйте компанию на платформе MAX для партнёров (**business.max.ru**,
   вход через Госуслуги / ИНН).
2. **Чат-боты → Создать бота**, задайте имя и адрес.
3. После модерации: бот → **Интеграция → Токен** → скопируйте в панель.

(Названия пунктов в кабинете MAX могут меняться — ищите раздел про чат-ботов и токен.)

### 6.9. Бот Telegram (запасной, только один)

1. Telegram → **@BotFather** → `/newbot`.
2. Имя бота и адрес, заканчивающийся на `bot`.
3. BotFather пришлёт токен вида `1234567890:AAH…` → в панель.

Если сервер в России и Telegram с него не открывается — укажите прокси в
«Настройках».

## 7. Сотрудники и роли

Раздел **«Сотрудники»**. Для каждого человека: имя, роль, при необходимости — логин
и пароль для панели, ID в MAX и Telegram (на этапе бота он сам подскажет сотруднику
его ID).

| Роль | Панель | Бот (с этапа 4) |
|---|---|---|
| **Администратор** | всё: подключения, сотрудники, тестирование, журнал, настройки | всё |
| **Руководитель** | обзор (с финансами) и журнал | всё, включая деньги |
| **Менеджер** | только обзор, **без финансов** | продажи, остатки, клиенты, задачи; выручка, прибыль, себестоимость и расчёты скрыты |
| **Сотрудник** | обычно не нужна | остатки, задачи, документы |

Права проверяются на сервере: даже если менеджер наберёт адрес раздела вручную,
он получит «Нет доступа», а попытка попадёт в журнал.

Защита от ошибок: нельзя снять роль администратора с самого себя, отключить себя
или удалить последнего администратора.

Если человек уволился — снимите галочку **«Сотрудник активен»**: он сразу потеряет
доступ, а история в журнале сохранится.

## 8. Проверка: экран «Тестирование»

Одна кнопка **«Проверить всё»** (10–30 секунд) проверяет три группы:

- **Сервер:** версия Python, место на диске, запись в базу, ключ шифрования и
  читаются ли им сохранённые пароли, точность часов, резервные копии, автозапуск,
  сменён ли пароль admin.
- **Сеть:** достаёт ли сервер до Claude, Wildberries, Ozon, Яндекс Маркета, Google,
  MAX, Telegram; открывается ли панель по внешнему адресу; работает ли HTTPS и
  сколько дней осталось сертификату.
- **Подключения:** все сразу, параллельно. Ошибка в одном не мешает проверке
  остальных.

Цвета: **зелёный** — работает, **жёлтый** — внимание (работает, но есть что
улучшить), **красный** — ошибка. У жёлтых и красных всегда есть строка
**«Что делать»**.

**«Скачать отчёт»** — текстовый файл для разработчика. Паролей, токенов и ключей в
нём нет — его можно спокойно пересылать.

Кроме того, платформа сама проверяет подключения каждые 6 часов (меняется в
«Настройках») и пишет в журнал, если что-то сломалось.

## 9. Журнал

Раздел **«Журнал»**: входы, изменения подключений и сотрудников, проверки,
отказы в доступе, ошибки. Фильтры — по важности (сведения / внимание / ошибка),
по разделу и поиск по словам.

Старые записи удаляются автоматически. Срок хранения (по умолчанию 90 дней) —
в «Настройках».

Технический журнал для разработчика лежит в файле `logs\app.log`.

## 10. Резервные копии и восстановление

**Что в копии:** база (подключения, сотрудники, журнал, настройки), ключ
шифрования, сертификат HTTPS, файл `.env`. Это всё, что нужно, чтобы поднять
платформу на новом сервере.

**Автоматически:** раз в сутки, хранятся последние 14 (меняется в «Настройках»).
Лежат в папке `backups`.

**Вручную:** «Настройки → Сделать копию сейчас» или **`резервная-копия.bat`**.

**Храните копии не только на сервере.** Раз в неделю скачивайте свежую копию
(«Настройки → Резервные копии → Скачать») на другой компьютер, флешку или в облако.
В копии есть ключ шифрования — храните её как пароли: в надёжном месте.

**Восстановление:**

1. Скопируйте файл копии (`backup-ГГГГ-ММ-ДД_…zip`) на сервер.
2. Перетащите его мышью на **`восстановить-из-копии.bat`** → нажмите **1**.
   (Если просто запустить файл — возьмётся самая свежая копия из папки `backups`.)
3. Запустите **`запустить.bat`**.

Перед восстановлением текущие данные тоже сохраняются копией — ничего не теряется.

**Перенос на новый сервер:** установите платформу на новом сервере
(разделы 1–2), затем восстановите копию со старого.

## 11. Что видно → что делать

| Что видно | Что делать |
|---|---|
| При установке: «не найден Python версии 3.11 или новее» | Установите Python 3.12 с python.org с галочкой «Add python.exe to PATH», запустите `установить.bat` снова |

| При запуске: «платформа не запустилась» | Запустите `установить.bat` ещё раз. Не помогло — пришлите разработчику `logs\app.log` |
| Браузер: «Не удаётся получить доступ к сайту» | Платформа не запущена — `запустить.bat`. С другого компьютера — проверьте брандмауэр (раздел 5.2) |
| Панель: «Нет доступа» | У вас роль без этого раздела. Администратор меняет роль в «Сотрудниках» |
| Панель: «Страница устарела» | Нажмите F5 и повторите действие |
| Вход: «Слишком много неудачных попыток» | Подождите 10 минут. Забыли пароль admin — `сбросить-пароль-администратора.bat` |
| 1С: «неверное имя пользователя или пароль» | Проверьте логин и пароль, войдя с ними в 1С обычным способом |
| 1С: «интерфейс OData не опубликован» | Конфигуратор → Публикация на веб-сервере → галочка «Публиковать стандартный интерфейс OData» → Опубликовать |
| 1С: «нет опубликованной базы» | Неверное имя в конце адреса (`/ka`). Скопируйте адрес из браузера, где работает 1С |
| 1С: «сертификат не подтверждён» | Снимите галочку «Проверять сертификат» в подключении 1С |
| 1С: «нет прав на OData» / «не выбран ни один объект» | 1С → Администрирование → Синхронизация данных → Настройка стандартного интерфейса OData |
| 1С: «не хватает свободной лицензии» | Закройте лишние сеансы 1С или докупите лицензии |
| Claude: «Ключ Claude API неверный» | Создайте новый ключ на platform.claude.com → API Keys |
| Claude: «отклоняет запросы из страны» | Укажите прокси в «Настройках» (раздел 6.1) |
| Google: «Доступ к аккаунту отозван или устарел» | «Переподключить аккаунт Google». Повторяется раз в неделю — нажмите «Publish app» в Google Cloud |
| Google: «Gmail API не включён» | console.cloud.google.com → APIs & Services → Library → Gmail API → Enable |
| Google: «не разрешает вход по этому адресу» | Откройте панель на сервере по http://localhost:8080 или по домену с https |
| WB: «срок действия токена истёк» / «истекает через N дн.» | Выпустите новый токен в кабинете WB и вставьте в подключение |
| Ozon/Маркет: «не принял ключ» | Выпустите новый ключ в кабинете, проверьте, что Client ID из того же кабинета |
| Telegram: «сервер не достаёт до api.telegram.org» | Укажите прокси в «Настройках» или пользуйтесь ботом MAX |
| «Системный прокси-сервер не пропускает запросы» | В Windows включён прокси (Параметры → Сеть и Интернет → Прокси) — разрешите на нём нужный адрес или отключите |
| Тестирование: «Ключ шифрования: пароли не читаются» | Файл `data\secret.key` заменён или потерян. Восстановите копию (раздел 10) или введите пароли подключений заново |
| Тестирование: «Часы расходятся с точным временем» | Параметры → Время и язык → «Установить время автоматически» → «Синхронизировать» |
| Тестирование: «Место на диске» жёлтое или красное | Освободите диск или увеличьте его в настройках виртуальной машины |
| Тестирование: «Резервных копий нет» / «больше недели назад» | «Настройки → Сделать копию сейчас», проверьте автозапуск |
| Тестирование: «Внешний адрес не открывается с сервера» | Откройте адрес с телефона через мобильный интернет. Открывается — всё в порядке. Нет — DNS, проброс порта, брандмауэр (раздел 5) |
| Непонятная ошибка | «Тестирование → Проверить всё → Скачать отчёт» и отправьте файл разработчику вместе с `logs\app.log` |

## 12. Что нельзя трогать

- **`data\secret.key`** — ключ шифрования. Без него все сохранённые пароли и токены
  превращаются в мусор. Не удалять, не заменять, не отправлять по почте.
  Он есть в каждой резервной копии.
- **`data\platform.db`** — база. Не открывать и не копировать, пока платформа
  работает (для копии есть `резервная-копия.bat`).
- **Папку `venv`** — её создаёт `установить.bat`. Если сломалась — удалите её
  целиком и запустите `установить.bat` снова.
- **Файлы `.py` в папке `app`** — это сама программа. Правки вносит только
  разработчик.
- **Файл `.env`** — править не нужно: порт меняется в «Настройках» или
  `сменить-порт.bat`.
- **Не запускайте платформу дважды** (например, вручную и автозапуском на разных
  портах) — две копии будут мешать друг другу.
- **Не выкладывайте** резервные копии, `data` и `logs` в общий доступ и не
  отправляйте в мессенджеры.
